# Read-path audit, 2026-11-05

Base: `1d072f62e72ed357c094a7f52b29327ed8cdd862` on
`sprint/serialize-audit`, library 2.1.1, wire format 2.0.

This audit covers the header's documented read surface and the helpers it
reaches. `serialize.c` is a compatibility translation unit that includes the
header. `STANDARD.md`, `README.md`, and `SECURITY.md` at that base define the
contracts used below. Line numbers refer to the base unless stated otherwise.
The entry-point map was written before changing the harness or runtime.

## Entry-point map

All names below are in `serialize.h`. **Bounded** means bounded under the
stated caller contracts; it is not a claim that arbitrary C pointers or
caller-modified stream structs are safe. The caller supplies live, nonoverlapping
source/destination allocations of the declared sizes, preserves the stream
struct, and keeps the source immutable during a read. The ordinary initializer
requires eight readable allocation bytes beyond the logical data. The padded
initializer is the supported path for an exact-length source.

No separate signed 8/16-bit, signed unranged, fixed 8/16-bit, wide-string,
JSON, self-describing array, or recursive decoder exists in this runtime.
Smaller signed ranges use `serialize_read_int`; Q8.8 fits the fixed32 entry
point. Wide integers remain exact two-lane integers. The runtime allocates no
memory. Bytes and strings perform linear work bounded by the supplied stream
and destination declarations; an application still chooses its packet-size and
callback-depth limits.

## Refusal and output state

Every documented scalar reader stages its result until all its groups and
content checks pass. The uint128 group helper is internal and writes only
temporary storage at its documented call sites. A failed primitive leaves its
public scalar unchanged. Byte/string buffer contents after refusal are
unspecified by the standard, and an object callback may have written earlier
fields; consumers must discard the refused object. No rollback guarantee is
invented by this audit.

The cursor limit is invariant on read. With a nonnegative `int` byte count,
`num_bits <= 8 * INT_MAX`; a successful cursor is in `[0, num_bits]` and a failed
cursor is exactly `num_bits + 1`. The largest transient addition is 32 bits,
well inside int64. The failure flag handles zero-bit paths; the cursor limit
handles positive-width paths. The reason remains the first refusal.

The width helpers explicitly handle zero before calling the compiler's
count-leading-zero intrinsics (`serialize.h:1177`, `serialize.h:1192`). The
128-bit helpers use unsigned lanes and shifts smaller than 64. Fixed-point
declaration validation rejects a negative integer/fraction width before any
shift or loop; positive integer widths make `storage_bits - integer_bits` safe
for the three constant storage widths. Only validated fraction counts reach
`serialize_raw_bound`, and its maximum is 127. No input-controlled loop is
unbounded.

The padding contract permits loading slack, never decoding it. Logical bounds
are checked before every word load and bulk copy. No source pointer or caller
allocation size can be inferred from a bare C pointer. Null or undersized
allocations and direct mutation of the public stream struct remain caller
misuse, not input-byte findings. Checked padded-size misuse traps as documented;
release builds refuse it without copying.

### sra-c-1: hostile-string fuzz oracle misses an accepted interior NUL

- **Location:** `fuzz.c:351` (the accepted-string case at the audited base).
- **Attacker input/effect:** the existing hostile-corpus seed
  `test/fuzz-corpus/utf8_interior_nul` carries a counted string containing a zero
  byte. The production reader correctly refuses it. If its NUL refusal is
  deleted by the repository's existing `string-embedded-nul` negative control,
  the base fuzz oracle checks only the `strlen` prefix and accepts the shortened
  view. The comment claims a length agreement the code never checks. This is an
  assurance gap, not a demonstrated production acceptance bug.
- **Severity:** low.
- **Reduction:** independently read the length on a copy of the incoming stream
  state, then require every accepted string's `strlen` to equal that counted
  length before checking UTF-8. Keep the existing corpus and the existing
  sabotage rule; add a bounded control that demands this exact oracle failure.
- **Pin:** `test/fuzz-corpus/utf8_interior_nul` and a `make fuzz-controls` target
  that uses `tools/sabotage.c` without changing the vendored corpus or rules.
  At the exact base, with only the new control recipe added, it fails:
  `fuzz control string-embedded-nul FAILED: the harness missed the deleted refusal`
  (`make` exit 2). The clean reader passed the same seed. After the fix,
  `make -j4 fuzz-controls` exits 0 and reports
  `fuzz control string-embedded-nul: counted-length oracle is red, as it must be`.
  The sabotaged run names the exact failed expression:
  `fuzz_check failed: strlen( string ) == (size_t) length`.
- **Status:** fixed and pinned in the harness; no runtime change.

No attacker-buffer-reachable runtime defect was established by source review.
The standalone internal UTF-8 and lane helpers are not promoted to public
validated APIs. Any such API expansion requires a separate design decision.

## Not done and limits

No profiling was requested or run. No runtime hot path, state transition, or
index arithmetic is changed; no TLA+ model exists in the base, and no model
check is claimed. The harness reads a copied stream to observe the existing
length rule; it does not change the decoder's state machine.

The native Windows, big-endian, C89 matrix, and sibling C++ differential gates
were not rerun; this card's requested Linux gcc, clang, sanitizer, and bounded
fuzz gates all ran. Bounded fuzzing and source review do not prove the absence
of every possible defect. The source review established no attacker-buffer-
reachable runtime finding under the stated caller contracts.

No vendored standard, conformance vector, or conformance-control expectation
is changed. No new dependency, public API, tolerance, or repair path is added.
No new runtime refusal was needed; the one fixed finding is a fuzz oracle gap.

Verdict: LAND for the audit deliverable and pinned harness reduction.
